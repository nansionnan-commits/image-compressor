# 图片一键压缩 v7

**直接拖图片/文件夹进窗口就能压缩。** 真 OS 拖拽，不是应用内的伪拖。

- 🎯 **无损压缩** / 💎 **极致保真** — 像素**数学零差异**（用 `ImageChops.difference(...).getbbox() is None` 验过）
- ⚡ **推荐压缩** — q=85 重编码，业界甜点，肉眼难辨
- 💾 **压最小** — q=80，省最多
- 🛒 **亚马逊主图** — 2000px JPG，符合 Amazon 主图要求
- 📦 **主图≤200KB** — 长边 1280px + 自动二分降质量，确保 ≤ 200KB
- 📦 **主图≤120KB** — 长边 1100px + 自动二分降质量，确保 ≤ 120KB

**默认是 ⚡ 推荐压缩**。纯 Python + Pillow，**不依赖 jpegoptim，不联网**，所有计算都在你这台电脑上跑。

## v7 新增：按目标体积压

做亚马逊主图经常要把每张图都压到 ≤ 200KB 或 ≤ 120KB。v6 之前只能手动试质量参数 + 自己看输出大小，浪费时间。

v7 新增 2 个一键预设：

| 预设 | 长边限制 | 目标体积 | 实测 |
|---|---|---|---|
| 📦 主图≤200KB | 1280px | 200KB | 4.7MB 输入 → 187KB（q=89 自动找到） |
| 📦 主图≤120KB | 1100px | 120KB | 4.7MB 输入 → 116KB（q=85 自动找到） |

**工作原理**：把输入图先按 `max_side` 等比缩放，然后在质量区间 [18, 92] 二分搜索，找到刚好 ≤ 目标的最高质量。降质量比硬降像素能保住更多细节。

降到底仍达不到目标（比如要求 ≤ 5KB）会强写最低质量 (q=18) 的结果，并在日志里标 **「未达标」**，绝不静默失败。

> 高级用户也可以在「显示自定义参数」里手动填入「目标体积」输入框，> 0 即自动切到目标模式。

## v7 修复：为什么 800KB 图会被「跳过」

旧版本遇到这种操作最容易出问题：

```
输出目录 = 原图目录的上级文件夹    (例: D:\Downloads)
原图路径: D:\Downloads\亚马逊产品主图\图1.jpg
旧逻辑: D:\Downloads\亚马逊产品主图\图1.jpg  ← 跟自己打架, 直接跳过
```

输出路径算出来后刚好等于原图 → 程序为了不覆盖原图直接报「目标已存在,跳过」。**不是 800KB 太大，不是压缩算法坏，是路径自己撞到自己**。

v7 修了两件事：

1. **`_safe_out_path()` 永远不可能算出等于原图的路径**
   撞了就自动改名：`<原名>_compressed.jpg` / `_compressed2.jpg` / ……

2. **重复运行不「全部跳过」**
   上一轮生成的压缩输出会被原子覆盖重写 `.tmp → os.replace()`，但不碰原图。

3. **原图永远是只读**
   任何分支都走 `_safe_out_path` + 原图真路径比对，物理上不可能被覆盖。

✅ = 测试通过 · ❌ = 不支持

| 拖什么 | 结果 |

| 拖一张图（中文名 / 带空格）| ✅ 加进队列 |

| 重复拖同一文件/文件夹 | ✅ 自动去重 |

**真实拖图验证步骤**：① 双击 exe ② 打开 Windows 资源管理器 ③ 找一张 `.jpg` ④ 用鼠标拖到 ImageCompressor 窗口里 ⑤ 看到文件出现在「待压缩文件」列表 ⑥ 点蓝色「▶ 开始压缩」→ 看「处理日志」滚动输出 ⑦ 完成看 `dist\compressed\<预设名>\` 下产出。

## 7 个预设

| 预设 | 原理 | JPG 省多少 | 画质 |
|---|---|---|---|
| 🎯 无损压缩 | 剥掉 EXIF，像素一个 bit 不动 | 5~20% | **零损失** |
| 💎 极致保真 | 同上，但保留 EXIF 拍摄信息 | 少一点 | **零损失** |
| ⚡ 推荐压缩 | q=85 重编码（业界甜点） | ~25% | 肉眼难辨 |
| 💾 压最小 | q=80 重编码 | 最多 | 细看能看 |
| 🛒 亚马逊主图 | 转 JPG + 长边 2000px + q=85 | 很多 | 好，且符合 Amazon 主图要求 |
| 📦 主图≤200KB | 长边 1280 + 二分搜索质量 | 自动达标 | 肉眼难辨 |
| 📦 主图≤120KB | 长边 1100 + 二分搜索质量 | 自动达标 | 肉眼难辨 |

按钮排成 2 行，一行挤不下会被截断：

```
[ 🎯无损压缩 ] [ 💎极致保真 ] [ ⚡推荐压缩 ] [ 💾压最小 ]
[ 🛒亚马逊主图 ] [ 📦主图≤200KB ] [ 📦主图≤120KB ]
```

**三个保命设计**：

1. **压完反而更大就自动保留原图**（无损预设除外）
   任何情况下压完 ≥ 原图的 95%，直接丢弃结果保留原图。

2. **小于 50KB 的图直接跳过**
   这种图不值得压。

3. **无损预设不再被「95% 门槛」挡住**
   像素零差异时再小的节省也是净收益。最低下限 1KB（避免为省几十字节去复制一个几 MB 的文件）。

## 无损是怎么做到的

`jpegoptim` 靠反复试参数来优化量化表，耗时长还依赖外部二进制。

本项目换了个思路：JPEG 文件里有一段一段的数据块，其中

- `APP0~APP15` = EXIF 拍摄参数、相机型号、**内嵌缩略图**
- `COM` = 注释

手机拍的照片，光这些就占 40KB+，但它们**根本不参与画面解码**。

`_jpeg_strip.py` 遍历所有段，把 APP/COM 丢掉，量化表、哈夫曼表、熵编码数据原样保留 → **像素完全一致，字节数下降**。

### 实测验证（v7 跑过的真实数据）

| 场景 | 结果 |
|---|---|
| 路径自撞（输出=原图上级目录）| ✅ 输出加 `_compressed` 后缀，不再报「目标已存在」 |
| 重复跑同一批 3 张 | ✅ 全部成功，不跳过，原图字节完全没变 |
| 7 个预设全跑一遍 | 全部走通（无损预设 8/8 像素零差异） |
| 200KB 预设 × 3 张不同尺寸 | 187KB / 197KB / 196KB，长边 1280px |
| 120KB 预设 × 3 张不同尺寸 | 116KB / 115KB / 119KB，长边 1100px |
| EXIF 真剥 | ✅ 原图有 EXIF，输出无 EXIF |
| 极难目标 (≤5KB) | ✅ 输出最低质量 (q=18) 结果 + 日志标「未达标」 |
| 中文/空格路径 + 4 张 | ✅ 4 张都成功 ≤ 200KB |

判定像素真零差异只用 `ImageChops.difference(a, b).getbbox() is None`。**不要用 Pillow 的 `Image.__eq__`，它不是按内容比较的，会误判**。

## 从源码重新打包成 `.exe`

```powershell
# 一次性
C:\Python314\python.exe -m pip install --upgrade pyinstaller pillow tkinterdnd2

# 打包 (在项目根目录)
C:\Python314\python.exe -m PyInstaller --onefile --noconsole ^
  --name ImageCompressor ^
  --collect-all tkinterdnd2 ^
  --collect-submodules tkinterdnd2 ^
  compress_images_gui.py

# 产物: dist\ImageCompressor.exe
```

`--collect-all tkinterdnd2` 是关键，不然 onefile 模式下 tkinterdnd2 的 tkdnd tcl/dll 找不到。

## 历史与回退

### v7 — 目标体积预设 + 路径自撞修复（2026-10）

- **新增 2 个预设**：📦 主图≤200KB / 📦 主图≤120KB，按亚马逊主图常用目标量自动二分搜索质量压到位
- 路径自撞修复：输出撞原图自动加 `_compressed` 后缀，不再误报「目标已存在」
- 重复运行不再「全部跳过」，上一轮的压缩输出会被原子覆盖重写
- 无损预设不再被 95% 智能回退门槛卡住，但设了 1KB 绝对下限避免复制几 MB 文件只为省几十字节
- 质量达到/未达标在日志里都明确写出（`ok|质量q=N` / `ok|质量q=N|未达标(...)`）
- 自定义面板新增「目标体积 (KB)」输入框 + 长边 1280/1100 选项
- 预览区实时显示目标体积、是否达标、未达标原因
- `_t_v7.py` 27 项回归全 PASS，`_t_gui_v7.py` 布局验证 OK，`_t_e2e_v7.py` 4 个场景 4/4 全 PASS

### v6 — Tkinter + tkinterdnd2 真 OS 拖拽（2026-10）

界面仍是 Tkinter（v4 的成熟形态），但**首次加入 tkinterdnd2** 接入了真 OS 拖拽：

- 之前 Tkinter 版（v4）只能用「选文件」按钮，不能从资源管理器拖
- 现在 Tkinter + tkinterdnd2 + `ImageChops.difference` 像素零损失校验 = 这次推荐的最稳形态
- 5 个预设、4 段列表（队列 / 预览 / 日志 / 状态栏）、自定义参数面板、可调输出目录
- 5 个预设按钮：**全部完整不截断**（默认 1000×880，最小 920×720）
- 右侧预览面板 wraplength=250/260，文字不会被截
- `_on_drop` 主路径用 `tk.splitlist` 解析 tkdnd 真实格式（带空格自动加花括号），加正则 + 整串路径兜底，8 种用例都不崩
- PyInstaller 6.22.3 onefile 打包 18.5 MB

### v5 — 已被回退

尝试过 Flet Material 3：UI 美、但 `DragTarget` 接不到 OS 资源管理器。每次首次启动还要下载 40 MB Flet 客户端。对「真 OS 拖拽」这条核心需求没什么用，回退到 Tkinter + tkinterdnd2 这条更稳的路。

### v4 之前

v4 = Tkinter 旧版基线（无法拖图）。v3 之前是命令行版 + 拖 BAT。这条历史只在 git log 里，不影响现在的使用。
